# A call's arguments built by the runner

Code: `crates/mini_racer_engine/src/request.rs` (`read`, `worth_building`, `buildable`, `Cursor::tag`); `crates/mini_racer_engine/src/runner.rs` (`invoke`, `terminate`); `crates/mini_racer_engine/src/control.rs` (`ControlBlock::termination_requested`, `IsolateTerminator`); the counts in `CallRequest` come from the encoder (`ext/mini_racer_rs/src/encode.rs`). Tests: `crates/mini_racer_engine/tests/call_arguments.rs`, against V8's reading. What a v8 bump can move here: v8-bump step 14.

A `Context#call`'s arguments are built by the runner (`request::read`) rather than V8's deserializer, which makes every array holey, so V8 serialized a returned argument as a sparse array. V8's deserializer builds objects faster than the runner's one API call per property, so the encoder counts the hashes it writes and their pairs (`CallRequest`), and the runner builds only a call with at most 4 pairs in all or at most 2 per hash on average (`request::worth_building`); any other call V8 reads whole, as before.

The runner builds numbers, BigInts, strings, dates, back references, packed arrays and objects, past the padding V8 skips before a value's tag (`Cursor::tag`); a two-byte string with a unit past Latin-1 it makes through V8's API, which keeps that one two-byte, from the request's bytes in place when the padding aligned them (`sys::units`), and V8 reads any other for it from that string's bytes alone, since V8's API would make it one-byte.

A binary (V8's API aborts the process where its deserializer throws when it cannot allocate the buffer), a key that is neither a string nor an int32, a key given twice, an array inside itself, an object of more than 64 keys and nesting past 64 leave the whole request to V8, decided from its bytes before the runner makes any value (`request::buildable`): objects made for a call then refused leave V8's read of it the shapes they generalized, so it writes an integer field back as a double, and hold their memory under `max_memory:` while V8 reads the call again.

A termination requested while the runner builds leaves the rest to V8 too: V8's deserializer acts on one before each value, so the builder checks `ControlBlock::termination_requested` before the request and before each value, and one requested before the dispatch refuses it first (`TermCell::refuses`). The flag is set before anything asks V8 to terminate and cleared only once V8 has cancelled, so every `terminate_execution` goes through `IsolateTerminator` or `runner::terminate`.
