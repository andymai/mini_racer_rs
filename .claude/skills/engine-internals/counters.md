# Counters

What a change here costs: the profiling skill's "What to measure first".

`MiniRacerRs.counters` reads a context's counts from atomics, without a dispatch or the context's lock: the `Counters` halves in the control block, one written by the thread dispatching and one by the runner. Dispatches, callbacks and bytes are counted as the caller sends and receives (`ContextHandle::dispatch`, `nested`, `await_response`, `Request::payload`), terminations by the cause each response reports, the runner's JavaScript time (`Timing`, `Request::runs_script`), and collections timed from V8's prologue to its epilogue (`Collections`, `sys::count_collections`); a forked child takes the counts over (`adopt`) or reads them (`ContextHandle::counters`).

Each half of a context's `Counters` has one writer at a time, the thread dispatching, which holds the context, or the runner, so an increment is a relaxed load and store rather than a locked add; a count written from any other thread would lose increments. `js_ns` costs the runner two clock reads per request that runs scripts, taken before its response, and a request nested in a callback is timed inside the callback's pause. A nested dispatch its caller abandoned ends without a cause of its own (`TermCell::interrupt`), so it counts as `interrupt`; `heap_exhausted` counts each dispatch the heap limit ended or a poisoned context refused (`MiniRacerRs::HeapLimitError`).
