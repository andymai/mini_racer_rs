# Startup snapshots and the blob

Code: `crates/mini_racer_engine/src/snapshot.rs` (`SnapshotBlob`, `SnapshotBlob::check`, `IntlGuard`); `crates/mini_racer_engine/src/sys.rs` (`startup_data`); `crates/mini_racer_engine/src/control.rs` (`ContextConfig`); `ext/mini_racer_rs/src/snapshot.rs` (`MiniRacer::Snapshot`, the copy `dump` hands out, the blobs `Snapshot.load` refuses). Tests: `crates/mini_racer_engine/tests/snapshot.rs`, `crates/mini_racer_engine/tests/snapshot_memory.rs`, `test/ruby/snapshot_test.rb`, `test/ruby/snapshot_blob_test.rb`. Overview: `ARCHITECTURE.md` "Snapshots"; following a new V8's blob layout: v8-bump step 12.

V8 reads a context's startup blob for as long as its isolate lives (each context it makes from it, each code cache it checks), so `ContextConfig::snapshot` stays in the control block, which the runner holds until it has dropped the isolate, and `sys::startup_data` hands V8 the shared bytes rather than a copy; a snapshot build holds its base the same way, and a control block that leaks an isolate leaks its blob with it. A `MiniRacer::Snapshot` makes its `SnapshotBlob` at a `Context.new` and reuses it, through a `WeakSnapshotBlob`, while a context made from it lives and its String holds the same bytes; once its contexts are gone (collected, not only disposed: a disposed context's handle keeps its control block) it holds the String, which `dump` hands out copies of, as mini_racer does, and the `Arc`'s 32 bytes the weak reference keeps. A `Weak` keeps its `Arc`'s allocation, so the blob's bytes have one of their own (`Arc<Box<[u8]>>`), freed with the last strong reference: kept inline, a 6.8 MiB snapshot's bytes stayed resident after its only context was collected and `malloc_trim` ran (`crates/mini_racer_engine/tests/snapshot_memory.rs`).

`SnapshotBlob::check` makes mini_racer's checks in its order and with its messages (`InvalidSnapshot`), on V8 15.2's blob layout (`SnapshotImpl` in V8's `snapshot.cc`, which 13.6 shares): the length, the version through V8's own check, the header, each section's offset, then the checksum V8 writes in word 8 over everything after it, Adler-32 (libv8-node's V8, built with zlib) or V8's own Fletcher-32 (the v8 crate's), either accepted. V8 checks none of that itself outside a debug build. Past mini_racer's checks it refuses, as `MiniRacer::SnapshotError` where mini_racer hands V8 the blob, a section that does not open with V8's magic number, pinned as `SnapshotBlob::MAGIC` and checked whole as V8 checks it, on which V8 aborts, or whose recorded payload runs past the section, which V8 reads that far without a check; a checksum is no defense, since whoever writes a blob can write one that matches.

An empty snapshot's warmup warms V8's own up, as mini_racer's does. A `Snapshot.new` script runs after mini_racer's `Intl` guard, word for word (`INTL_GUARD`): it refuses a script that read or wrote `Intl` and puts `Intl` back after one that did not, looking up only own properties, so nothing a script left on `Object.prototype` runs then; a warmup has no guard.
