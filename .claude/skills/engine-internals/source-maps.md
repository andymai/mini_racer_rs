## Parsing and rewriting

`mini_racer_sourcemap` parses a regular version 3 map (base64 VLQ of at most seven digits, `sourceRoot`, refusing index maps and other versions, `sourcesContent` skipped unread) in time linear in its bytes, with caps on the map's bytes, its lines, segments, sources, names and the length of a source (`MAX_MAP`, `MAX_LINES` and the rest; sources, names and the root checked as they are read), and keeps sources and a root free of control characters. It checks a map against its bundle, follows V8's line breaks (LF, CRLF, lone CR, U+2028, U+2029) with the correction for those a map's generator does not count, counts columns in UTF-16, looks up positions on one generated line, finds a bundle in an eval's source after a prefix, and rewrites the locations of frames paired with V8's detailed frames, read from the message's end, with the search past a first frame line that does not pair held to runs of 4,096 lines.

## Registering and matching

`MiniRacerRs.register_source_map(bundle, map)` parses the map once, without the GVL (`rb_raw::nogvl`, from copies of both Strings), into the process's registry (`process::source_maps`): at most 8 bundles, found by content, so a bundle given again takes its own place with its new map; a forked child starts from a copy, try-locked, and registers past it, so a child forked while another thread holds the registry's lock, which it holds only to swap a map in, starts without maps. It refuses a bundle under 1 KiB (`MIN_BUNDLE`), which could turn up in unrelated code, a bundle String in ISO-8859-1 or UTF-16LE, which `Context#eval` sends as Latin-1 or UTF-16, a map past 256 MiB before reading it, and a source or root holding a control character, U+2028, U+2029 or a bidi control, which a backtrace line would print.

A map keeps its bundle's only copy in a `memchr` two-way finder built at registration, so a search is linear however the bundle repeats itself and a forked child never waits on one built on demand. Before an eval's script runs, a UTF-8 source at least as long as the shortest bundle is searched for the longest bundle it holds (`runner::match_bundle`); Latin-1 and UTF-16 sources, startup snapshots and a fast call's template are never matched. A match records the script's id, where the bundle starts in it and the name V8 prints for it (its source URL, else its file name), the latest 16 per context, which a child taking the context over copies; a source evaluated again in a context gets the same script back from V8's compilation cache, so its entry is replaced, map and all.

The match turns on `set_capture_stack_trace_for_uncaught_exceptions(true, 10)` for that isolate for good. The flag changes nothing JavaScript reads (stacks, call sites, `Error.stackTraceLimit` at 0, 3, 50, deleted or not a number, `Error.captureStackTrace`, scripts compiled from the code cache, all compared with an isolate without it, and `leaves_what_javascript_reads_alone` in the engine's tests), but V8 then captures a detailed trace with each error and with the message the runner's `TryCatch` makes for every throw: about 0.1 µs more per `new Error` at the top of a stack and 0.8 µs twenty frames down, and 0.2 µs and 1 µs more per caught `throw` of a non-Error; React and MUI renders measured the same.

Only a `JsErrorKind::Runtime` message is rewritten (`runner::relocated`), paired with the exception's detailed trace, else its message's, by `mini_racer_sourcemap::rewrite`, which reads the frame lines that end the message from its end, pairs them from the first and, only when that disagrees and the run is at most 4,096 lines, searches later starts: async frames, frames past the tenth, `eval` and `new Function` code inside the bundle, and the frames of a stack overflow whose functions had no positions yet (V8's detailed frames for those all read 1:1, so the pairing fails) keep V8's locations, as does a whole message whose frames do not pair. A user `Error.prepareStackTrace` writing V8's own format and positions is rewritten as V8's text is.
