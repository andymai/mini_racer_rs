# Eval sources copied without the GVL

Code: `ext/mini_racer_rs/src/context.rs` (`source_text`, `Sent`, `SOURCE_WITHOUT_GVL`); `ext/mini_racer_rs/src/rb_raw.rs` (`read_without_gvl`). Tests: `test/ruby/large_eval_source_test.rb`, `test/diff/corpus/shared-sources.json` (large Latin-1 and UTF-16LE sources against mini_racer's).

An eval's source of a megabyte or more (`SOURCE_WITHOUT_GVL`) is copied for the request with the GVL released, so Ruby's other threads run during the copy: in a cached load of a 44 MB server rendering bundle, the longest a second thread went without running fell from 18.4 to 0.5 ms (medians of 9 fresh processes each), and the eval took as long as before (124 and 125 ms). A shorter source, a file name, a `Snapshot.new` or `warmup!` source and a callback's error message are still copied under the GVL.

The copy reads a frozen share of the String (`rb_str_new_frozen`, which hands the buffer to a new frozen String that the original then shares), held in `read_without_gvl`'s frame: while the thread is blocked, a collection on another thread scans that stack conservatively, so it neither frees nor moves the share, and `black_box` keeps it there until the call returns. A thread that changes the String meanwhile copies it before writing, so the eval reads the source as it was given. The original keeps sharing the frozen buffer afterwards, so its next change copies it once, under the GVL.

`rb_nogvl` with `RB_NOGVL_INTR_FAIL` skips the copy when an interrupt is already pending; `check_ints` then runs it, as `MiniRacerRs.register_source_map` does: after a trap the copy is tried again, up to twice before it runs with the GVL held, and a `Thread#raise`, `Thread#kill` or `Timeout` raises before anything is sent. The copy itself is not interruptible (its unblock function does nothing): an interrupt that arrives during it stays pending for the dispatch's wait, as one that arrived during a copy under the GVL did. Nothing is sent until the copy is whole, and the context's lock is not held yet, so a trap that runs between tries may use the context.
