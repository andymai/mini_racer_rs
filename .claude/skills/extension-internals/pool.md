# `MiniRacerRs::Pool`

Code: `ext/mini_racer_rs/src/pool.rs`; `ext/mini_racer_rs/src/rb_raw.rs` (`yield_ensuring`, `thread_create`); `ext/mini_racer_rs/src/gc_root.rs` (`spawn`); `ext/mini_racer_rs/src/options.rs` (`size:` and `max_uses:`, Ruby-free). Tests: `test/ruby/pool_test.rb`, `test/ruby/fork/*pool*_case.rb`, `test/stress/pool_churn.rb`.

A pool builds its contexts before `new` returns and runs the setup block for each. Checkouts go one per fiber, a nested one reusing its fiber's context; waiting checkouts go in arrival order, each popping a `Thread::Queue` of its own and looking again every 100 ms, with a freed context reserved for the first (`waiting`, `hand_off`). The checkin is marked from the ensure of the block (`rb_raw::yield_ensuring`) and finished after it (`settle`). A context retires after `max_uses:`, out of memory or disposal, with the replacement built on a thread of the pool's own (`start`, `replace`, `gc_root::spawn`); a failed build is raised at the next checkout. A forked child rebuilds (`reconcile`), and `#shutdown` ends the pool, after which a checkout raises `ShutdownError`.

`MiniRacerRs::Pool` keeps its state in `Cell`s touched only under the GVL and holds no Rust lock, so a fork finds nothing locked: a child compares `fork::epoch()` at every checkout, checkin and shutdown, forgets every slot without disposing it (`reconcile`), and builds its own contexts on threads of its own, since a fork leaves its parent's build threads behind.

A checkin runs inside `rb_ensure` (`rb_raw::yield_ensuring`, as `File.open` closes its file), where a Ruby method call could take an interrupt (`rb_funcall` checks for one as it returns) that nothing would raise, so it only marks the slot; `settle` starts the replacement's thread, disposes a context checked in after shutdown and hands what is free to the first waiting checkout once `rb_ensure` has returned.

A checkout that finds others waiting waits behind them, so a thread that checks in and asks again at once cannot take the context back before the woken one runs; a trap handler or a finalizer that checks out on a fiber already waiting takes that wait's place and any context reserved for it (`place_of`), since the wait cannot go on until the handler returns. The handler waits on a queue of its own, and the displaced wait is owed a wakeup (`owed`) that a thread of the pool's own pushes from the next `settle` on any thread, or from `#shutdown`, with each queue kept rooted in `owed` until the array handed to that thread holds it: a timed `Queue#pop` misses a push made while a trap handler runs on its thread, since the handler's return puts the thread back to sleep.

After a captured break, throw or `Thread#kill` (`ErrorType::Jump`), Ruby resumes from what the execution context holds, which a Ruby call could overwrite, so then nothing is settled: the next checkout starts what is pending and hands on what is free, a waiting checkout looks again within 100 ms (`RESCAN_SECONDS`), and `#shutdown` called again disposes what is left; a pool thread killed midway leaves its slot pending the same way.

A pool thread reads its pool back from its own hidden instance variable (`gc_root::spawn`), which compaction updates: a copy held in the thread's closure goes stale when the pool moves before the thread first runs. The block's exception is told from a `$!` left by earlier code by comparing `rb_errinfo` before the yield with what `rb_ensure` leaves for the ensure, so re-raising an earlier exception inside the block also counts as raised.
