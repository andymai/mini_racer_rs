# The decoder's scratch buffer

Code: `ext/mini_racer_rs/src/decode.rs` (`RubyVisitor::scratch`, `SCRATCH`); `crates/mini_racer_wire/src/text.rs` (`latin1_to_utf8_into`, `utf16le_to_utf8_into`, `latin1_utf8_len`, `utf16le_utf8_len`). Tests: `test/ruby/result_strings_test.rb`. The transcoders' throughput: `cargo bench -p mini_racer_wire --bench wire`.

A Latin-1 or UTF-16 string value is transcoded in one pass into the decoder's scratch buffer (`RubyVisitor::scratch`), which has room for the longest UTF-8 the text could be (two bytes per Latin-1 byte, three per UTF-16 unit) and is zeroed only as it grows, then copied into its String with one `rb_enc_str_new`; text whose UTF-8 could pass 64 KiB (`SCRATCH`) is measured first (`latin1_utf8_len`, `utf16le_utf8_len`) and gets a buffer of exactly its size, freed once copied, since the longest it could be would commit up to three times its size next to the String. Writing into an `rb_str_buf_new` String and setting its length instead, as json 3.1's parser does for escaped strings, measured slower: it takes three Ruby calls, two of them under `rb_protect`, and a buffer zeroed or measured first, which cost more than the copy saves. A UTF-16 string with a lone surrogate still becomes a UTF-16LE String, as in mini_racer.
