# Release Flow reference

## Versions

`lib/mini_racer_rs/version.rb` holds the version, and release-please (release type `ruby`) rewrites its first literal. `release-please-config.json` also bumps `workspace.package.version` in `Cargo.toml`. release-please runs no resolver, so `.github/workflows/release-please.yml` checks out its PR branch and runs `scripts/sync-release-locks.sh`, which rewrites the gem's entries in `Gemfile.lock` and `test/consumers/transitive/Gemfile.lock`, runs `cargo update --workspace`, and updates `mini_racer_wire` and `mini_racer_sourcemap` in the fuzz crate's own `crates/mini_racer_wire/fuzz/Cargo.lock`. `scripts/check-versions.sh` fails when any of these disagree with `lib/mini_racer_rs/version.rb` or with `.release-please-manifest.json`. Commits touching only `.claude`, `.github`, `bench`, `scripts`, `test`, `tools/compat`, `tools/reference` or a crate's `tests`, `examples` or `fuzz` directory never count toward a release; `exclude-paths` names each directory, so a new one needs its own entry. The release PR merges only while `RELEASE_HOLD` is exactly `false`.

## Native gems

The loader (`lib/mini_racer_rs.rb`) loads `lib/mini_racer_rs/<ruby minor>/mini_racer_rs.<dlext>` when it exists, else `lib/mini_racer_rs/mini_racer_rs.<dlext>` (a source build). A native gem therefore holds one extension per Ruby in `[release] rubies`, and its `required_ruby_version` runs from the oldest of them to below the next minor after the newest. `rakelib/package.rake` builds it in `tmp/package/<platform>` from the source gem's file list minus `Cargo.*`, `crates/` and `ext/`, with no extensions to build and no `rb_sys` dependency; it refuses to build without an extension for every listed Ruby, or with one for an unlisted Ruby. The six platforms are listed in `rakelib/package.rake`, `.github/workflows/release.yml`, `scripts/publish-gems.sh` and the files `scripts/check-platforms.sh` already compares, and that script fails when they drift.

Each compile leg of `.github/workflows/release.yml` builds with the release profile stripped of debug info and local symbols (`CARGO_PROFILE_RELEASE_DEBUG`, `CARGO_PROFILE_RELEASE_STRIP`), `--remap-path-prefix` for the workspace and `CARGO_HOME`, and `MACOSX_DEPLOYMENT_TARGET` from `[release] macos`, then checks the exported symbols, the glibc or macOS floor, and that the extension evaluates `1+1`. glibc legs run on `ubuntu-22.04` and `ubuntu-22.04-arm`, whose glibc is the floor; Apple Silicon on `macos-15`, Intel on `macos-15-intel`. musl legs run `scripts/alpine.sh compile` in `ruby:<minor>-alpine`, the newest Alpine, on `ubuntu-24.04` and `ubuntu-24.04-arm` with the same environment, and check only the exports: their floor is an install test. Every Alpine image the release and CI run is pinned to its multi-arch index digest in `release/alpine/Dockerfile`, read through `scripts/alpine-image.sh`; `scripts/check-action-pins.sh` fails on a container image anywhere in `.github` without a digest. `SOURCE_DATE_EPOCH` is set to the commit time only while packaging, never while compiling.

## Install tests

Every native gem is installed into an empty `GEM_HOME` on its platform for every Ruby, on the same runners as the compile legs, and `release/smoke.rb` runs from outside the checkout: it checks the loaded gem's platform, then evaluates, calls, attaches a callback, checks ICU data, a timeout and a snapshot. The job then copies the installed extension for its Ruby into the checkout's `lib/mini_racer_rs/<minor>/` and runs the Ruby tests (with plain `ruby`, since rake's compile task needs Rust) and the upstream and ExecJS suites in strict mode on it, so the full suites cover the released build; a failing leg uploads `tmp/upstream`. A musl gem installs in a stock `ruby:<minor>-alpine` image, which has no compiler, through `scripts/alpine.sh install`, which then adds build tools for the suites' own gems. `install-musl-floor` also installs each musl gem on Ruby 3.4 in the oldest Alpine the gems support, the `floor` image, and smoke-tests it only. The source gem is installed the same way on TruffleRuby (which loads upstream's backend and builds nothing) and on a plain `ubuntu-24.04` runner with its own Rust and no V8 archive prefetched, so `ext/mini_racer_rs/extconf.rb`'s pinned digest is what downloads V8.

## Publishing

The publish job runs only for a release tag, on the `release` event or a manual run with `publish` set, and only after its environment's reviewer approves. It verifies `SHA256SUMS`, exchanges the job's OIDC token through RubyGems' configure-rubygems-credentials action (trusted publishing, no stored API key), and runs `scripts/publish-gems.sh`, which refuses a directory holding anything but the six platform gems and the source gem, skips any gem RubyGems.org already lists at that version and platform, and pushes the platform gems before the source gem. Before it, the `sign` job runs `scripts/sign-gems.sh`, which signs each gem through Sigstore with that job's OIDC identity from the bundle locked with checksums in `release/sign` (never an unpinned `gem exec`), at most 2 minutes a gem, and uploads the bundles as an artifact. It has no `environment`, so its token cannot be exchanged for a RubyGems.org key (the trusted publisher requires `rubygems`), and it is `continue-on-error`, so the publish runs whether or not signing worked. `scripts/publish-gems.sh` pushes a gem with the Sigstore bundle downloaded next to it when one is there. A gem that fails to sign, or whose signed push fails, is pushed without one with a `::warning::`, so check the sign and publish logs for those. Dependabot updates to `release/sign` are never auto-merged; CI's Sign Bundle job checks that the bundle installs with a checksum for every gem. RubyGems.org takes attestations only through trusted publishing, so a dry run never signs. The gems, their Sigstore bundles and `SHA256SUMS` are then attached to the GitHub release. Build provenance is attested for every gem on tag runs.
