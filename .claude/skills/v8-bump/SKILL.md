# V8 Bump

`v8` is pinned exactly in `Cargo.toml` (`workspace.dependencies.v8`) and Dependabot ignores it, as it ignores `deno_core_icudata`: the engine loads ICU data through `v8::icu::set_common_data_78` in `crates/mini_racer_engine/src/process.rs`, so the ICU data crate moves with V8's ICU version. A bump changes the archive digests, the export allowlists, the wire goldens and the third-party notices together, in one PR.

## Procedure

1. Pick the version. The Extended workflow's "Newest v8 crate" job writes the pinned and newest versions to its summary every week and shows what breaks; read rusty_v8's release notes for the V8 version it carries.
2. Set the pin in `Cargo.toml` and run `cargo update -p v8`. If V8's ICU major changed, move `deno_core_icudata` to the matching release and rename the `set_common_data_<major>` call.
3. `scripts/update-v8-archives.sh` downloads every target's archive and source binding and rewrites `ext/mini_racer_rs/v8-archives.sha256`; then `. scripts/fetch-v8-archive.sh`.
4. Build and fix API changes: `scripts/gate.sh --quick`, then `cargo nextest run --workspace --exclude mini_racer_rs`.
5. Exports: `scripts/check-exports.sh --write` on Linux. For macOS, a failing "Check exports" step in CI's `ruby` job uploads the built list as the `exports-macos-15-ruby-<version>` artifact; commit its `exports.allow.macos`.
6. Wire goldens: `cargo run -p mini_racer_engine --example gen_wire_golden`, then `UPDATE_GOLDEN=1 cargo test -p mini_racer_wire --test golden`, and read every changed `.txt`. A new wire version or tag is a `mini_racer_wire` change first.
7. Notices: `scripts/update-notices.sh`. It fails when an archive links source that `licenses/v8/components.tsv` does not list; add the component and its license there.
8. Ruby: `test/ruby/loader_test.rb` checks the V8 major and minor in `MiniRacerRs::V8_VERSION`; update it, then `bundle exec rake test`.
9. Parity: open the PR with the `ledger-generate` label and merge the ledgers (parity-suite skill). A message that changed only with V8's wording becomes `deviation:behavior:v8-version@ruby`, with its evidence.
10. `scripts/check-boundaries.sh` still holds: V8's sandbox and pointer compression features stay off.
11. V8's worker tasks go to the engine's own pool through three slots of `v8::Platform`'s vtable, which `crates/mini_racer_engine/src/sys.rs` (`worker_vtable`) replaces in a copy of rusty_v8's `CustomPlatform` vtable: `NUMBER_OF_WORKER_THREADS` (6), `POST_TASK_ON_WORKER_THREAD_IMPL` (20) and `POST_DELAYED_TASK_ON_WORKER_THREAD_IMPL` (21). Recount them from v8-platform.h in the new v8 crate's source, under the cargo registry (two destructor slots first, then every `virtual` in declaration order). The copy is `PlatformVtable`, the two words before the first slot (offset to top, type info) and 22 slots: `nm -C -S lib/mini_racer_rs/mini_racer_rs.so | grep 'vtable for CustomPlatform'` must still show `00000000000000c0`, and a different size changes `PlatformVtable` with it (`CustomPlatform` must declare no virtual function of its own past `v8::Platform`'s). The replacements take `this`, the `uint8_t` priority, the task, then for the delayed one the `double` delay in the first floating point register, then the `SourceLocation` by reference: V8's libc++ marks `std::unique_ptr` `trivial_abi`, so the task travels as a pointer in a register and the callee owns it. Check that in the callee, `DefaultPlatform::PostTaskOnWorkerThreadImpl` (and the delayed one), disassembled in each pinned archive (the task arrives in `rdx` on x86_64, `x2` on arm64), and in a caller, `DefaultJobState::NotifyConcurrencyIncrease` (`call *0xa0(...)` on x86_64, slot 20, with the new task in `rdx`). A task is run and deleted through rusty_v8's `v8__Task__Run` and `v8__Task__DELETE`, which a rename turns into a link error. Also confirm that rusty_v8's `v8__Platform__NewCustomPlatform` (its `binding.cc`) still makes a request for 0 threads `std::thread::hardware_concurrency()` held to 1 through 16, which `process::workers::configure` sizes the pool by (`sysconf(_SC_NPROCESSORS_ONLN)`, what libc++ returns on Linux), and still accepts 1. `sys::tests::the_worker_slots_are_v8s_own` posts through the slots of an unpatched platform and fails when one is wrong, on the CI leg that runs the Rust tests (ubuntu-24.04 x86_64); on the other targets a wrong slot 20 leaves `test/ruby/fork/multi_threaded_child_compiles_wasm_in_a_new_context_case.rb` hanging, as its child has no thread of V8's.
12. Snapshot blobs: `SnapshotBlob::check` in `crates/mini_racer_engine/src/snapshot.rs` follows V8's blob header and section layout, from `SnapshotImpl` in `snapshot.cc` and `SnapshotData` in `snapshot-data.h`, in the new v8 crate's V8 source under the cargo registry; compare both with the new V8 and update the offsets and the comment naming the V8 version. `every_blob_v8_writes_is_accepted` and `refuses_a_blob_v8_would_abort_on` in `crates/mini_racer_engine/tests/snapshot.rs` fail when the layout moved.
13. The PR runs `.github/workflows/release.yml` as a dry run, since it changes the archive pins: every platform and Ruby builds, checks its exports and floors, and installs (release-flow skill).
14. A call's arguments and its primitive results cross without V8's deserializer and serializer where the bytes allow, which leans on three things a bump can move. `sys::is_smi` reads a handle's tagged word, which holds only while rusty_v8 builds V8 without direct handles (`v8_enable_direct_handle = false` in V8's gni/v8.gni under the crate's source). `serialize::primitive` writes the format version V8's serializer writes, read once per context, and V8's bytes for each primitive (`WriteSmi`, `WriteHeapNumber`, `WriteOddball`, `WriteString` with its two-byte padding, in V8's value-serializer.cc). `request::read` looks for a termination before the request and each value, where V8's deserializer acts on one (the `STACK_CHECK` in `ReadObject`, which those in `ReadDenseJSArray` and `ReadJSObject` follow with nothing between), and builds each value as V8 reads it; it leaves a call holding a binary to V8 because `v8::ArrayBuffer::New` aborts where `NewJSArrayBufferAndBackingStore` lets the deserializer throw, and has V8 read a two-byte string because the API's `Factory::NewStringFromTwoByte` makes a one-byte string of what fits. `crates/mini_racer_engine/tests/results.rs` and `crates/mini_racer_engine/tests/call_arguments.rs` compare both with V8's own bytes and outcomes; when one fails, recheck those places in the new source.
15. The heap limit follows V8's heap sizing: `Heap::ConfigureHeap` in `heap.cc` (which flags size the heap in place of `CreateParams::heap_limits`, `SIZING` in `crates/mini_racer_engine/src/process/platform.rs`, and the semi-space rounding `runner::most_reserved` bounds), `ResourceConstraints::ConfigureDefaultsFromHeapSize` in `api.cc` (the young generation's share), the value implications in `flag-definitions.h` that set `max_semi_space_size`, `Heap::RestoreHeapLimit` (no lower than the live heap and a quarter, which `runner::recover` checks before putting a limit back), `Heap::InvokeNearHeapLimitCallback` and its callers, and `SetFlagsFromString` and `SplitArgument` in `flags.cc` (which `read_sizing` follows). `flags_that_size_the_heap_override_the_limit_and_are_refused` and `limits_of_any_size_are_taken_without_flags` in `crates/mini_racer_engine/tests/heap_limit.rs` fail when a flag's effect or V8's own sizing moved; rerun the minimum's evidence (`MIN_HEAP_LIMIT`) when the young generation's sizing changes.
