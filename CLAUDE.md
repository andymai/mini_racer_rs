# mini_racer_rs

Rust replacement for the `mini_racer` gem 0.22.2: same `MiniRacer` API, V8 from the `v8` crate (rusty_v8), Ruby bindings through magnus and rb-sys. The parity bar is mini_racer's own test suite, run unmodified.

## Hard rules

- Rust owns behavior. Ruby under `lib/` is vocabulary only: constants, the error hierarchy, `MiniRacer::Binary`, the loader, and the pure compositions `Context#load` and `#write_heap_snapshot`. The one exception is upstream's TruffleRuby backend, `lib/mini_racer/truffleruby.rb` and `lib/mini_racer/shared.rb`, vendored byte for byte and never edited.
- Intra-gem loads use `require_relative`.
- `unsafe` lives only in the modules `layers.toml` fences (`engine::sys`, `ext::rb_raw`, `ext::guard`, `ext::gc_root`), one operation per block, each with a `// SAFETY:` comment.
- rb-sys is called only from `ext/mini_racer_rs/src/rb_raw.rs`. Release the GVL only through `rb_raw::nogvl` and run interrupts only through `rb_raw::check_ints`, so no Ruby exception unwinds through a Rust frame.
- Ruby methods are defined only through `export!`; every `extern "C"` body calls `guard()` or `catch_unwind`.
- Ruby values kept in Rust storage go through `ext/mini_racer_rs/src/gc_root.rs`.
- Process-global engine state lives in `crates/mini_racer_engine/src/process.rs` and its submodules.
- Behavior that differs from mini_racer 0.22.2 is a deliberate deviation with a failing-first test and a recorded reason.
- No en or em dashes anywhere: code, comments, docs, commit messages. `scripts/check-prose.sh` enforces it.
- Comments explain a non-obvious why and nothing else.
- Never `--no-verify`, `HUSKY=0`, or a hook edit to get past a failing hook; `.claude/hooks/block-bypass.py` refuses them (a tripwire; CI is the gate).
- Public prose (README, docs, gemspec text, the repository description, anything filed upstream) goes through the `outward-writing` skill and Andy's approval. PR titles and bodies go through outward-writing and open once the fact-check and checker pass.

## Layers

`layers.toml` is the source of truth; `scripts/check-boundaries.sh` fails CI if this table drifts from it.

| Crate | Layer | Path | Role |
|---|---|---|---|
| `mini_racer_sourcemap` | L0 | `crates/mini_racer_sourcemap` | Source maps for stack traces: parsing, lookup, rewriting frame locations; `forbid(unsafe_code)` |
| `mini_racer_sync` | L0 | `crates/mini_racer_sync` | Concurrency protocol types; `forbid(unsafe_code)` |
| `mini_racer_wire` | L0 | `crates/mini_racer_wire` | V8 wire format codec; `forbid(unsafe_code)` |
| `mini_racer_engine` | L1 | `crates/mini_racer_engine` | V8 process state, flags, runners; the only crate that names `v8` |
| `mini_racer_rs` | L2 | `ext/mini_racer_rs` | The Ruby extension (cdylib); the only crate that names magnus or rb-sys |

## Invariants

- I1: isolate-scoped V8 calls run only on the thread that owns or locks that isolate. Other threads reach it only through `IsolateHandle` (terminate, cancel, interrupt).
- I2: an isolate's custody is on its runner's stack or deposited in its control block; a deposit with an idle channel is the only fork-recoverable state.
- I3: Ruby values live in Rust storage only through `gc_root`; the decoder holds them only in native stack locals.
- I4: every FFI entry point is panic-guarded.
- I5: each channel message is delivered exactly once.
- I6: no Ruby non-local exit crosses a Rust frame; jumps resume only after the Rust frames below the method entry have returned.
- I7: lock order is GVL, then context lock, then the engine's process locks; no engine lock is held while waiting for the GVL.
- I8: V8-owned objects are dropped on a thread of the current fork generation: a runner, or for a worker task, a thread of that generation's worker pool.

## Pitfalls

- `lib/mini_racer_rs/version.rb` holds one version literal; release-please rewrites the first one it finds, and the Cargo workspace version. `scripts/sync-release-locks.sh`, which the release PR workflow runs, brings both `Gemfile.lock`s, `Cargo.lock` and the fuzz crate's `Cargo.lock` along; `scripts/check-versions.sh` fails until they agree.
- Loom builds need `--cfg loom` in `RUSTFLAGS` and their own `--target-dir target/loom`; sharing the default target dir rebuilds everything on every switch.
- The fuzz crate is its own workspace with its own `Cargo.lock` (checked by `cargo fetch --locked`, cargo deny and cargo audit); it builds only on the nightly pinned as `toolchains.fuzz` in `tools/versions.toml`, which `scripts/fuzz-smoke.sh` installs when missing.
- `rake compile` builds the dev profile locally and release when `CI` is set (`RB_SYS_CARGO_PROFILE`).
- A stale `lib/mini_racer_rs/mini_racer_rs.so` keeps loading after Rust edits until `rake compile` runs; `NATIVE_VERSION` only catches version mismatches. An extension copied into `lib/mini_racer_rs/<minor>/` (from a native gem) wins over that build until it is deleted. Switching profiles (`CI=1 rake compile` after a dev build, or back) can reinstall the other profile's copy staged under `tmp/<platform>/mini_racer_rs/<ruby version>/`, which make finds newer than cargo's output; delete it and `lib/mini_racer_rs/mini_racer_rs.so` first, and check with `cmp` against `target/release/libmini_racer_rs.so`.
- Without the variables from `scripts/fetch-v8-archive.sh`, cargo downloads V8 itself and skips the pinned digest. v8's build script unpacks the archive into `<target>/<profile>/gn_out/obj`, outside its own build directory, and rust-cache keeps the build script's recorded output but not that directory, so a CI change that rebuilds the v8 crate without rerunning its build script (a feature or version change in a crate below v8) fails with `could not find native static library rusty_v8` unless `scripts/restore-v8-static-lib.sh`, which the setup action runs after the cache, has put the library back; the newest-v8 canary in `extended.yml`, which skips the setup action's V8 steps, cleans v8 instead. Locally a missing `gn_out` fails the same way once the v8 crate is rebuilt; run the script, or `cargo clean -p v8` (with `--release` for a release build).
- A dependency, toolchain or v8 change regenerates `THIRD_PARTY_NOTICES.md` (`scripts/update-notices.sh`); it downloads every pinned V8 archive and fails if one links source that `licenses/v8/components.tsv` does not list.
- cargo-about installed from source needs `--features cli`; `bin/setup` passes it.
- V8's platform and flags are process-global and freeze at first use, so tests that set flags run in their own process.
- `mini_racer_rs.gemspec` lists files by explicit globs; a new file outside them is missing from the gem.
- On Ruby 4.0, `bundle install` builds the `fiddle` gem, which needs libffi's headers (`libffi-devel` on Fedora, `libffi-dev` on Debian and Ubuntu, or `PKG_CONFIG_PATH` at Homebrew's libffi); older Rubies use their default `fiddle`. The fork cases that call libc's `fork()` need it, and under `CI` a fork case that skips fails instead.
- Source builds need libclang; with the `libclang` gem, `ext/mini_racer_rs/extconf.rb` also passes GCC's include directory to bindgen.
- On musl (Alpine), cargo refuses the extension's cdylib unless `RUSTFLAGS` holds `-C target-feature=-crt-static`: rb_sys passes it to rustc alone, so `ext/mini_racer_rs/extconf.rb` adds it for `rake compile`, and plain cargo that builds the extension crate needs it in `RUSTFLAGS` too: `scripts/madvise-fixture.sh` hits the cdylib refusal, and `cargo test -p mini_racer_rs --lib` a build script linked static, where bindgen cannot load libclang (`Dynamic loading not supported`). The other crates build and test without it. `scripts/fetch-v8-archive.sh` picks the musl archive when `ldd --version` names musl; the glibc archive links there too and the extension then fails to load (`__vfprintf_chk: symbol not found`). BusyBox `ps` has no `-p`, so whatever reads resident memory reads `/proc/self/status` on Linux. `scripts/alpine.sh` writes to the checkout as its owner, which under a rootless podman without `--userns=keep-id` is root, and as root the watchdog test that sets `RLIMIT_NPROC` skips. The upstream ledgers name a musl leg as they name the glibc one (`ruby-3.4-linux-x86_64`).
- Each git worktree needs its own `npm ci` before the commit hooks can run, and `git submodule update --init` before the upstream suites or `rake test` (the ExecJS autodetect test) can run.
- The upstream suites run from their submodule (`vendor/mini_racer` or `vendor/execjs`) with `BUNDLE_GEMFILE`, `RUBYOPT`, `MINI_RACER_RS_UPSTREAM_REPORT`, `MINI_RACER_RS_UPSTREAM_ROOT` and, for ExecJS, `EXECJS_RUNTIME` set by `test/upstream/run.rb`; run them through that script, not with `rake test` inside the submodule.
- A forked child takes over a single-threaded context only if its runner was idle at a fork that went through `Process._fork` or `Process.daemon`; every other inherited context raises `MiniRacer::RuntimeError` (`single-threaded runner: ...`). The child never frees or waits on anything inherited: it reads atomics and try-locks only. Processes are told apart by `process::fork::epoch()`, never by pid.
- V8's worker tasks never reach V8's own worker threads, which do not survive a fork: `process::ensure_initialized` points the platform at a copy of its vtable whose `NumberOfWorkerThreads` and `PostTaskOnWorkerThreadImpl`/`PostDelayedTaskOnWorkerThreadImpl` slots (6, 20, 21) lead to `engine::sys`, which posts to the current generation's pool (`process::workers`). V8's own pool is created with the one thread rusty_v8 cannot go below and never gets a task. Each process starts its pool's threads at its first worker task, as many as V8 would have run for the mode (the processors online, held to 1 through 16, or 1 under `:single_threaded`); a child never touches its parent's pool, and tasks queued there at the fork are abandoned. V8's idle workers wait on an Abseil condition variable with their records on their own stacks, so a child that posted to them read freed memory and aborted on Ubuntu's glibc, as mini_racer's children still do; the pool's idle threads wait on a std `Condvar` instead, and the child does not post to them either.
- A fork through `Process._fork` or `Process.daemon` waits, in both V8 platform modes, up to 500 ms for every runner to be idle or parked, then pauses the worker pool until the parent handler and waits up to 100 ms more for the tasks it is running to end (`fork::prepare`, `Workers::pause`); it goes ahead either way. Past either bound a child's new contexts are best effort again, and it refuses every inherited context.
- V8 accepts a code cache for any source of the same length and runs the code it holds, so `process::code_cache` finds an entry only by file name, startup snapshot, length and a digest keyed with the process's random `RandomState`; never key it by length or an unkeyed hash. A sighting's sampled digest finds nothing: it decides only whether a script was seen before, so its cache is built at the second sighting, and whether a context keeping its own copy computes the full digest; a context sharing the source computes it from the first sighting (`Plan::Compile(Some(key))`). The cache is built in `serve_one` after the dispatch, so it never counts against `timeout:`, and before the response, so a fork after the eval finds the runner idle; a `Building` claim makes contexts loading a script at once build it once and frees the key on any failure.
- A large script reads its source, from its first sighting and under the code cache's key, from one copy in `process::sources`, one byte a unit when every unit fits Latin-1 and two otherwise, as V8 stores a string of it. V8 reads a string's units for as long as the string lives and releases its reference through `sys::release_one_byte` or `release_two_byte` once, on whatever thread runs it: in a collection, in an isolate's teardown, or when it internalizes a live string, which hands the units to the internalized string or, if that one has its own, releases them then (`MigrateExternalString` in V8's `string.cc`), so those touch only the `Arc`'s count. The list drops a source only once its count is back to `held`, the references its own list and every ancestor's hold, so V8 never frees one: a forked child adds a reference to its parent's, never touches the parent's list and frees nothing it inherited, and an isolate a control block leaks keeps its strings' references. A copy no string reads that only one context ever read, as a script evaluated once has, goes at the next `Sources::units` call, that is the next large eval of a source shared or kept (`reading` takes the list's lock but sweeps nothing), which looks its own source up first; contexts are told apart by `Runtime::reader`, recorded under the list's lock (`Readers`), since V8's releases touch only the count. A copy no string reads that two or more contexts have read, read in turn or at once, a copy made again of one of the last 8 sources swept (`List::swept`), so short-lived contexts loading two scripts in turn convert each twice and then keep both, and every copy a forked child inherited stay resident, up to 8 sources or 256 MiB, until a new source needs its room: going idle and `low_memory_notification` release nothing, and a forked child that evicts an inherited copy drops only its own reference, so the copy stays for that process's life; one that inherited contexts it refuses still read counts as read there for good. Past 8 sources or 256 MiB still read, a context keeps its own copy, as do one with `max_memory:`, whose heap holds mini_racer's copy, and invalid UTF-8, whose replacements are left to V8's decoder; room is decided under the lock before a source is converted, from the fewest bytes it can take or, for one converted before and refused, invalid UTF-8 included, the size the list remembers. `MINI_RACER_RS_CODE_CACHE=off` turns sharing off with the cache. A context reading a shared source reports it in `heap_stats`' `external_memory`, by its length in characters, and not in its `used_heap_size` (`behavior:shared-source-heap-stats@ruby`).
- An eval with no file name in one of two shapes runs a template its context compiled once instead of compiling the source (`fast_calls`, `runner::fast_call`): ExecJS 2.10.2's `call`, `(<path>.apply(this, <JSON array>))`, and react-rails 3.2.1 and 3.3.1's render, `compose_js`'s wrapper, whitespace and all, in ExecJS's parentheses around one `this.ReactRailsUJS.serverRender('<function>', '<component>', <props>)`. The template is a top-level script like the source, with each literal replaced by a call to a native function held in a global `const` with a random name, so frames, line and column numbers, messages and `this` are the source's. It reads a render's values as the source would only while the call line runs once, at the wrapper's top level, so the code before and after the call must compile alone as a function body and hold no backtick, `eval`, `caller`, `\u` escape, or `arguments` other than as a property after a `.` on the same line, both checked once per template and kept with it; a source that starts and ends as a refused template takes the normal path unread. Short of reflection (`CallSite#getFunction` through `Error.prepareStackTrace`, or `caller` and `arguments.callee` through names built at run time), the call line then runs once, synchronously, at the wrapper's top level. Parity is the bar: whatever the recognizer or V8's JSON parser is not sure of (another shape, values that are not JSON, `__proto__` in any spelling, nesting past 128, a line break in a render's props, a template over 1 MiB, `verbose_exceptions:`) takes the normal path, as does a source equal to the context's last fast call, which V8's compilation cache runs faster from its second time; a new shape lands only with tests pinning its outcomes to mini_racer 0.22.2. Only reflection still tells the paths apart, the approved deviation `behavior:fast-calls@ruby`: `CallSite#getScriptHash`, `CallSite#getPosition` past the hoisted literals, and a render's wrapper, which sloppy code reaches through `caller` or `CallSite#getFunction`: its source shows the reads, and calling it again runs the call with no values outside a fast call and with that call's values during one; and `Context#heap_snapshot` shows the reader's `const`. `MINI_RACER_RS_FAST_CALLS=off` (unstable, read once per process) sends every eval down the normal path.
- V8 reads a context's startup blob for as long as its isolate lives (each context it makes from it, each code cache it checks), so `ContextConfig::snapshot` stays in the control block, which the runner holds until it has dropped the isolate, and `sys::startup_data` hands V8 the shared bytes rather than a copy; a snapshot build holds its base the same way, and a control block that leaks an isolate leaks its blob with it. A `MiniRacer::Snapshot` makes its `SnapshotBlob` at a `Context.new` and reuses it, through a `WeakSnapshotBlob`, while a context made from it lives and its String holds the same bytes; once its contexts are gone (collected, not only disposed: a disposed context's handle keeps its control block) it holds the String, which `dump` hands out copies of, as mini_racer does, and the `Arc`'s 32 bytes the weak reference keeps. A `Weak` keeps its `Arc`'s allocation, so the blob's bytes have one of their own (`Arc<Box<[u8]>>`), freed with the last strong reference: kept inline, a 6.8 MiB snapshot's bytes stayed resident after its only context was collected and `malloc_trim` ran (`crates/mini_racer_engine/tests/snapshot_memory.rs`). `SnapshotBlob::check` makes mini_racer's checks in its order and with its messages (`InvalidSnapshot`), on V8 15.2's blob layout (`SnapshotImpl` in V8's `snapshot.cc`, which 13.6 shares): the length, the version through V8's own check, the header, each section's offset, then the checksum V8 writes in word 8 over everything after it, Adler-32 (libv8-node's V8, built with zlib) or V8's own Fletcher-32 (the v8 crate's), either accepted. V8 checks none of that itself outside a debug build. Past mini_racer's checks it refuses, as `MiniRacer::SnapshotError` where mini_racer hands V8 the blob, a section that does not open with V8's magic number, pinned as `SnapshotBlob::MAGIC` and checked whole as V8 checks it, on which V8 aborts, or whose recorded payload runs past the section, which V8 reads that far without a check; a checksum is no defense, since whoever writes a blob can write one that matches. An empty snapshot's warmup warms V8's own up, as mini_racer's does. A `Snapshot.new` script runs after mini_racer's `Intl` guard, word for word (`INTL_GUARD`): it refuses a script that read or wrote `Intl` and puts `Intl` back after one that did not, looking up only own properties, so nothing a script left on `Object.prototype` runs then; a warmup has no guard.
- A `Context#call`'s arguments are built by the runner (`request::read`) rather than V8's deserializer, which makes every array holey, so V8 serialized a returned argument as a sparse array. V8's deserializer builds objects faster than the runner's one API call per property, so the encoder counts the hashes it writes and their pairs (`CallRequest`), and the runner builds only a call with at most 4 pairs in all or at most 2 per hash on average (`request::worth_building`); any other call V8 reads whole, as before. The runner builds numbers, BigInts, strings, dates, back references, packed arrays and objects, past the padding V8 skips before a value's tag (`Cursor::tag`); a two-byte string with a unit past Latin-1 it makes through V8's API, which keeps that one two-byte, from the request's bytes in place when the padding aligned them (`sys::units`), and V8 reads any other for it from that string's bytes alone, since V8's API would make it one-byte. A binary (V8's API aborts the process where its deserializer throws when it cannot allocate the buffer), a key that is neither a string nor an int32, a key given twice, an array inside itself, an object of more than 64 keys and nesting past 64 leave the whole request to V8, decided from its bytes before the runner makes any value (`request::buildable`): objects made for a call then refused leave V8's read of it the shapes they generalized, so it writes an integer field back as a double, and hold their memory under `max_memory:` while V8 reads the call again. A termination requested while the runner builds leaves the rest to V8 too: V8's deserializer acts on one before each value, so the builder checks `ControlBlock::termination_requested` before the request and before each value, and one requested before the dispatch refuses it first (`TermCell::refuses`). The flag is set before anything asks V8 to terminate and cleared only once V8 has cancelled, so every `terminate_execution` goes through `IsolateTerminator` or `runner::terminate`.
- mini_racer sends a String's bytes as UTF-8 unless its encoding is ISO-8859-1 or UTF-16LE, so every one of them that is all ASCII goes as one-byte text instead, the same characters, which V8 copies where it would scan for the first non-ASCII byte (`Encoder::string`). Whether it is ASCII comes from the coderange Ruby keeps in the String's flags (`rb_raw::cached_ascii`), else from its bytes, never from `rb_enc_str_coderange`: that scan checks each character of non-ASCII text, which made a call with an unscanned 1 MB non-ASCII String several times slower. Nothing writes the coderange back, so a String sent again is read again. A coderange a C extension left stale after changing the bytes would be trusted, as Ruby itself trusts it, and so would one set without a scan: on Ruby 3.3, `rb_usascii_str_new` and `rb_usascii_str_new_cstr` mark their String 7-bit unread (3.4 and 4.0 mark only an empty one, and `rb_usascii_str_new_static` marks nothing), so non-ASCII bytes a C extension passes them go as Latin-1 where mini_racer sends them as UTF-8. V8's deserializer decodes UTF-8 a byte at a time, twice, past its first non-ASCII byte, so a value's other text of 16 bytes up to 8 MiB (`text::LONG`) goes as what V8 would decode it to, decoded by simdutf (`Transcoder::decode`): one byte a character when each is at most U+00FF, else UTF-16 after the padding V8's serializer writes (`Writer::utf16_aligned`). Text simdutf finds invalid stays UTF-8, so its replacement characters are V8's own, and so does longer text: decoded, it takes a buffer of two bytes per byte and a request up to twice its length under the GVL, which would take a 100 MB String with one character past Latin-1 to about 500 MB at its peak, against 200 MB as UTF-8. Keys and a call's name keep mini_racer's form, since the runner builds only calls whose keys are UTF-8 or ASCII; the runner's strings come out the same either way, since rusty_v8's `String::new_from_utf8` decodes UTF-8 through simdutf as well. So the gain is in calls V8 reads whole; in a call the runner builds, the decoding only moves into the encoder, under the GVL, and a long Latin-1 value alone measured a little slower there.
- `MiniRacerRs.register_source_map(bundle, map)` parses the map once, without the GVL (`rb_raw::nogvl`, from copies of both Strings), into the process's registry (`process::source_maps`): at most 8 bundles, found by content, so a bundle given again takes its own place with its new map; a forked child starts from a copy, try-locked, and registers past it, so a child forked while another thread holds the registry's lock, which it holds only to swap a map in, starts without maps. It refuses a bundle under 1 KiB (`MIN_BUNDLE`), which could turn up in unrelated code, a bundle String in ISO-8859-1 or UTF-16LE, which `Context#eval` sends as Latin-1 or UTF-16, a map past 256 MiB before reading it, and a source or root holding a control character, U+2028, U+2029 or a bidi control, which a backtrace line would print. A map keeps its bundle's only copy in a `memchr` two-way finder built at registration, so a search is linear however the bundle repeats itself and a forked child never waits on one built on demand. Before an eval's script runs, a UTF-8 source at least as long as the shortest bundle is searched for the longest bundle it holds (`runner::match_bundle`); Latin-1 and UTF-16 sources, startup snapshots and a fast call's template are never matched. A match records the script's id, where the bundle starts in it and the name V8 prints for it (its source URL, else its file name), the latest 16 per context, which a child taking the context over copies; a source evaluated again in a context gets the same script back from V8's compilation cache, so its entry is replaced, map and all. The match turns on `set_capture_stack_trace_for_uncaught_exceptions(true, 10)` for that isolate for good. The flag changes nothing JavaScript reads (stacks, call sites, `Error.stackTraceLimit` at 0, 3, 50, deleted or not a number, `Error.captureStackTrace`, scripts compiled from the code cache, all compared with an isolate without it, and `leaves_what_javascript_reads_alone` in the engine's tests), but V8 then captures a detailed trace with each error and with the message the runner's `TryCatch` makes for every throw: about 0.1 µs more per `new Error` at the top of a stack and 0.8 µs twenty frames down, and 0.2 µs and 1 µs more per caught `throw` of a non-Error; React and MUI renders measured the same. Only a `JsErrorKind::Runtime` message is rewritten (`runner::relocated`), paired with the exception's detailed trace, else its message's, by `mini_racer_sourcemap::rewrite`, which reads the frame lines that end the message from its end, pairs them from the first and, only when that disagrees and the run is at most 4,096 lines, searches later starts: async frames, frames past the tenth, `eval` and `new Function` code inside the bundle, and the frames of a stack overflow whose functions had no positions yet (V8's detailed frames for those all read 1:1, so the pairing fails) keep V8's locations, as does a whole message whose frames do not pair. A user `Error.prepareStackTrace` writing V8's own format and positions is rewritten as V8's text is.
- A primitive result (a small integer, a heap number other than NaN, a string, a boolean, null, undefined) is written by `serialize::primitive` without V8's serializer, under the format version V8 writes, read once per context: for these V8's serializer checks for no termination and runs no script, and the microtasks it would run as it returns have run as the script returned. A heap number holding an int32 is still a double to V8, so `sys::is_smi` reads the handle's tagged word, which assumes V8 built without direct handles; `crates/mini_racer_engine/tests/results.rs` compares each kind with V8's own bytes.
- Each half of a context's `Counters` has one writer at a time, the thread dispatching, which holds the context, or the runner, so an increment is a relaxed load and store rather than a locked add; a count written from any other thread would lose increments. `js_ns` costs the runner two clock reads per request that runs scripts, taken before its response, and a request nested in a callback is timed inside the callback's pause. - A string key of an object or a map is made interned (`Visitor::key`, `rb_raw::interned_utf8`), the frozen String `Hash#[]=` would keep in place of a new one, so it is the object mini_racer's key is; keys of objects inside arrays and sets go through a cache for the decode, as names do in json 3.1's parser (63 keys of at most 55 bytes that start with a letter). - The decoder recurses once per level of a result, up to 95, and of a callback's arguments, up to 96 with the arguments array, as mini_racer's limits fall, so whatever its recursive functions keep inline is repeated on the stack of the fiber or thread that decodes: in a release build that is `value` and the container being read, about 300 bytes a level for every shape, so a result 95 deep needs about 30 KiB past the point where Ruby refuses a method call, where mini_racer 0.22.1 needs about 10. A key is read in `entry_key`, out of line, and read again by `value` when it is not a string, since handing `value` its tag split `value` in two and pulled every container into one frame over twice as large; `Pairs::start` and `KeyCache::start` make the decoder's buffers out of line too. A stack that runs out under Rust frames faults, and Ruby's handler jumps over them to raise, so nothing they own is freed and a lookup or a context's lock they hold is never released. Instead, a container that begins deeper than any checked before asks Ruby whether less than its margin for a C function is left (`RubyVisitor::check_stack`, `rb_raw::stack_exhausted`), as a callback does before decoding its arguments (`RubyHost::run`), and both raise `SystemStackError` with Ruby's `stack level too deep` as an ordinary error (`behavior:stack-exhaustion@ruby`). A callback refused there has no room left to call `to_s`, so `message` hands JavaScript that text itself. Every class a decode or its errors name is resolved at load (`decode::init`, `encode::init`, `errors::init`, `gc_root::init`), since a `StaticRoot` resolved first near the end of the stack panics on the `SystemStackError` its lookup raises. `ContextDeepResultsTest` in `test/ruby/context_test.rb` decodes each shape 95 deep in a fiber and a thread at Ruby's default stack sizes, and `test/ruby/stack/` converts results and callback arguments 95 deep at gaps short of the end of Ruby's smallest stacks; a debug build's frames are many times larger, so it refuses every one of those.
- A decoded hash takes its pairs when it ends, in one `rb_hash_bulk_insert` into its still empty table (`Pairs`), which keeps a repeated key as `Hash#[]=` does: the first key's place and object with the last value. A key that is not a String of class String, an Integer, a Float, a Symbol, nil, true or false (`rb_raw::plain_key`), such as a Hash or an Array that refers back to an open hash, first puts every open hash's waiting pairs in, so its `hash` and `eql?` see each one as mini_racer has built it by then, and goes in by itself; a hash that already holds pairs takes the rest one by one, since a bulk insert would rehash it whole. Past 128 values the waiting pairs move to a `gc_root::Spill`, whose mark pins them.
- A Latin-1 or UTF-16 string value is transcoded in one pass into the decoder's scratch buffer (`RubyVisitor::scratch`), which has room for the longest UTF-8 the text could be (two bytes per Latin-1 byte, three per UTF-16 unit) and is zeroed only as it grows, then copied into its String with one `rb_enc_str_new`; text whose UTF-8 could pass 64 KiB (`SCRATCH`) is measured first (`latin1_utf8_len`, `utf16le_utf8_len`) and gets a buffer of exactly its size, freed once copied, since the longest it could be would commit up to three times its size next to the String. Writing into an `rb_str_buf_new` String and setting its length instead, as json 3.1's parser does for escaped strings, measured slower: it takes three Ruby calls, two of them under `rb_protect`, and a buffer zeroed or measured first, which cost more than the copy saves. A UTF-16 string with a lone surrogate still becomes a UTF-16LE String, as in mini_racer.
- mini_racer can abort the whole process (signal 6), as 0.22.1 did on a `Map` with a function key; the differential run records that as a `crash` outcome, and worker stderr is in `tmp/diff/<role>-worker.log`. A worker that exits with a status instead is a harness failure and stops the run.
- `MiniRacerRs.heap_limit = bytes` (32 MiB through 4 GiB, `nil` for none) is read at each `Context.new`, so it holds for ExecJS's contexts too, and passed to V8 by `runner::sized`: `CreateParams::heap_limits(0, bytes)` splits it into a young generation of three semi-spaces of 2 to 32 MiB and the rest old, but V8 15.2 rounds a semi-space up to a power of two, which reserved up to a tenth more than the limit, so `sized` rounds it down and gives the old generation the rest, and V8 reserves the limit, less its rounding of the old generation down to a 256 KiB page. `heap_limits` also makes the code range the limit's size, on which V8 aborts the process unless it is a multiple of the allocation page (100,000,000 bytes did), so `sized` leaves the code range at V8's own size, as for a context without a limit; `MiniRacerRs.heap_limit` reads back the value set. V8 calls the near-heap-limit callback (`sys::watch_heap_limit`, registered with the control block) when the old generation cannot grow, which it may do from a thread other than the runner, so the callback touches only `HeapWatch`'s atomics and the termination cell: it requests `HeapExhausted` for the armed dispatch, unless the runner is collecting on its own, and lends V8 room up to three times the old generation's limit at once, since V8 asks only around its last-resort collection and retries the allocation once before it aborts: lent half the limit at a time, a growing `Map`'s new backing store aborted at limits of 40, 80, 160 and 320 MiB. Past that room V8 aborts as it would without a limit: a `JSON.parse` whose result is about twice the limit did from 16 MiB down, and at 48, 96 and 192 MiB under `--minor-ms`. V8 sizes the heap from `max_old_space_size`, `max_heap_size` or `max_semi_space_size` in place of the limit, and `predictable_gc_schedule` implies a semi-space larger than a small limit gives, so those flags and a limit refuse each other with `ArgumentError`. `read_sizing` follows `SetFlagsFromString` and fails closed: every argument of a flag up to `--` counts, `--no` forms, a value V8 reads from the next argument and a later argument V8 might never reach included, and only a flag that is one argument V8 reads whole (`--max_old_space_size=0`) clears an earlier one. Whatever it misses, a context V8 sizes past the limit is refused at `Context.new` with `ArgumentError`; `optimize_for_size` and `stress_compaction` imply a 1 MiB semi-space, which only shrinks the heap, and are taken. After a dispatch in which V8 called the callback, `recover` collects in full and puts the limit back only when the live heap and a quarter fit under it, since V8's `RestoreHeapLimit` goes no lower than that; a heap that does not fit poisons the context, which then refuses every eval, call, microtask checkpoint and pump with its own message until disposed. It also collects after a script terminated with the heap that full, which V8 otherwise reports through the callback in the next script. A script that hit the limit has its leftover microtasks dropped rather than drained: V8 empties the queue when a termination reaches it there. `HeapExhausted` is not a pending cause (`CauseSet::PENDING`): it ends with the dispatch it arrived in, as `recover` settles the heap then, so leftover microtasks of a stopped or timed-out script that reach the limit report it with that script, it outranking the stop or timeout, a microtask checkpoint whose microtasks reach it raises it itself, and one landing as a result serializes without stopping it is dropped. A child that takes a capped context over registers the callback again with its own block (`runner::adopt`), as the inherited one names the parent's; removing the callback when none is registered is V8's `UNREACHABLE`. ArrayBuffer backing stores, shared sources and snapshot builds are outside the limit; `max_memory:` works as before beside it.
- Plain V8 has no `MessageChannel` or `TextEncoder`, which React's server renderer reaches for when it loads; `test/consumers/js/entries/ssr-globals.js` provides the stand-ins SSR setups on mini_racer use. Bundles are built into `tmp/consumers/bundles` by `npm run build` in `test/consumers/js`.
- `MiniRacerRs::Pool` keeps its state in `Cell`s touched only under the GVL and holds no Rust lock, so a fork finds nothing locked: a child compares `fork::epoch()` at every checkout, checkin and shutdown, forgets every slot without disposing it (`reconcile`), and builds its own contexts on threads of its own, since a fork leaves its parent's build threads behind. A checkin runs inside `rb_ensure` (`rb_raw::yield_ensuring`, as `File.open` closes its file), where a Ruby method call could take an interrupt (`rb_funcall` checks for one as it returns) that nothing would raise, so it only marks the slot; `settle` starts the replacement's thread, disposes a context checked in after shutdown and hands what is free to the first waiting checkout once `rb_ensure` has returned. A checkout that finds others waiting waits behind them, so a thread that checks in and asks again at once cannot take the context back before the woken one runs; a trap handler or a finalizer that checks out on a fiber already waiting takes that wait's place and any context reserved for it (`place_of`), since the wait cannot go on until the handler returns. The handler waits on a queue of its own, and the displaced wait is owed a wakeup (`owed`) that a thread of the pool's own pushes from the next `settle` on any thread, or from `#shutdown`, with each queue kept rooted in `owed` until the array handed to that thread holds it: a timed `Queue#pop` misses a push made while a trap handler runs on its thread, since the handler's return puts the thread back to sleep. After a captured break, throw or `Thread#kill` (`ErrorType::Jump`), Ruby resumes from what the execution context holds, which a Ruby call could overwrite, so then nothing is settled: the next checkout starts what is pending and hands on what is free, a waiting checkout looks again within 100 ms (`RESCAN_SECONDS`), and `#shutdown` called again disposes what is left; a pool thread killed midway leaves its slot pending the same way. A pool thread reads its pool back from its own hidden instance variable (`gc_root::spawn`), which compaction updates: a copy held in the thread's closure goes stale when the pool moves before the thread first runs. The block's exception is told from a `$!` left by earlier code by comparing `rb_errinfo` before the yield with what `rb_ensure` leaves for the ensure, so re-raising an earlier exception inside the block also counts as raised.
- A `Weak` keeps its `Arc`'s allocation, so nothing long-lived holds one to a disposed context: the watchdog's heap entries name a context by address, and its one weak reference to each lives in `Timers::blocks` until the context's runner exits (`watchdog::forget`), and a dead one found there is replaced by the next context at its address or dropped when its entry comes due, while the fork generation's registry drops its dead ones at the next `register`.
