# mini_racer_rs

Rust replacement for the `mini_racer` gem 0.22.1: same `MiniRacer` API, V8 from the `v8` crate (rusty_v8), Ruby bindings through magnus and rb-sys. The parity bar is mini_racer's own test suite, run unmodified.

## Hard rules

- Rust owns behavior. Ruby under `lib/` is vocabulary only: constants, the error hierarchy, `MiniRacer::Binary`, the loader, and the pure compositions `Context#load` and `#write_heap_snapshot`. The one exception is upstream's TruffleRuby backend, `lib/mini_racer/truffleruby.rb` and `lib/mini_racer/shared.rb`, vendored byte for byte and never edited.
- Intra-gem loads use `require_relative`.
- `unsafe` lives only in the modules `layers.toml` fences (`engine::sys`, `ext::rb_raw`, `ext::guard`, `ext::gc_root`), one operation per block, each with a `// SAFETY:` comment.
- rb-sys is called only from `ext/mini_racer_rs/src/rb_raw.rs`. Release the GVL only through `rb_raw::nogvl` and run interrupts only through `rb_raw::check_ints`, so no Ruby exception unwinds through a Rust frame.
- Ruby methods are defined only through `export!`; every `extern "C"` body calls `guard()` or `catch_unwind`.
- Ruby values kept in Rust storage go through `ext/mini_racer_rs/src/gc_root.rs`.
- Process-global engine state lives in `crates/mini_racer_engine/src/process.rs` and its submodules.
- Behavior that differs from mini_racer 0.22.1 is a deliberate deviation with a failing-first test and a recorded reason.
- No en or em dashes anywhere: code, comments, docs, commit messages. `scripts/check-prose.sh` enforces it.
- Comments explain a non-obvious why and nothing else.
- Never `--no-verify`, `HUSKY=0`, or a hook edit to get past a failing hook; `.claude/hooks/block-bypass.py` refuses them (a tripwire; CI is the gate).
- Public prose (README, docs, gemspec text, the repository description, anything filed upstream) goes through the `codex-write` skill and Andy's approval. PR titles and bodies go through codex-write and open once the fact-check and checker pass.

## Layers

`layers.toml` is the source of truth; `scripts/check-boundaries.sh` fails CI if this table drifts from it.

| Crate | Layer | Path | Role |
|---|---|---|---|
| `mini_racer_sync` | L0 | `crates/mini_racer_sync` | Concurrency protocol types; `forbid(unsafe_code)` |
| `mini_racer_wire` | L0 | `crates/mini_racer_wire` | V8 wire format codec; `forbid(unsafe_code)` |
| `mini_racer_engine` | L1 | `crates/mini_racer_engine` | V8 process state, flags, runners; the only crate that names `v8` |
| `mini_racer_rs` | L2 | `ext/mini_racer_rs` | The Ruby extension (cdylib); the only crate that names magnus or rb-sys |

## Invariants

- I1: isolate-scoped V8 calls run only on the thread that owns or locks that isolate. Other threads reach it only through `IsolateHandle` (terminate, cancel, interrupt).
- I2: an isolate's custody is on its runner's stack or deposited in its control block; a deposit with an idle channel is the only fork-recoverable state.
- I3: Ruby values live in Rust storage only through `gc_root`; the decoder holds them only in native stack locals.
- I4: every FFI entry point is panic-guarded.
- I5: each channel message is delivered exactly once.
- I6: no Ruby non-local exit crosses a Rust frame; jumps resume only after the Rust frames below the method entry have returned.
- I7: lock order is GVL, then context lock, then the engine's process locks; no engine lock is held while waiting for the GVL.
- I8: V8-owned objects are dropped on a thread of the current fork generation: a runner, or for a worker task, a thread of that generation's worker pool.

## Pitfalls

- `lib/mini_racer_rs/version.rb` holds one version literal; release-please rewrites the first one it finds, and the Cargo workspace version. `scripts/sync-release-locks.sh`, which the release PR workflow runs, brings both `Gemfile.lock`s, `Cargo.lock` and the fuzz crate's `Cargo.lock` along; `scripts/check-versions.sh` fails until they agree.
- Loom builds need `--cfg loom` in `RUSTFLAGS` and their own `--target-dir target/loom`; sharing the default target dir rebuilds everything on every switch.
- The fuzz crate is its own workspace with its own `Cargo.lock` (checked by `cargo fetch --locked`, cargo deny and cargo audit); it builds only on the nightly pinned as `toolchains.fuzz` in `tools/versions.toml`, which `scripts/fuzz-smoke.sh` installs when missing.
- `rake compile` builds the dev profile locally and release when `CI` is set (`RB_SYS_CARGO_PROFILE`).
- A stale `lib/mini_racer_rs/mini_racer_rs.so` keeps loading after Rust edits until `rake compile` runs; `NATIVE_VERSION` only catches version mismatches. An extension copied into `lib/mini_racer_rs/<minor>/` (from a native gem) wins over that build until it is deleted.
- Without the variables from `scripts/fetch-v8-archive.sh`, cargo downloads V8 itself and skips the pinned digest.
- A dependency, toolchain or v8 change regenerates `THIRD_PARTY_NOTICES.md` (`scripts/update-notices.sh`); it downloads every pinned V8 archive and fails if one links source that `licenses/v8/components.tsv` does not list.
- cargo-about installed from source needs `--features cli`; `bin/setup` passes it.
- V8's platform and flags are process-global and freeze at first use, so tests that set flags run in their own process.
- `mini_racer_rs.gemspec` lists files by explicit globs; a new file outside them is missing from the gem.
- On Ruby 4.0, `bundle install` builds the `fiddle` gem, which needs libffi's headers (`libffi-devel` on Fedora, `libffi-dev` on Debian and Ubuntu, or `PKG_CONFIG_PATH` at Homebrew's libffi); older Rubies use their default `fiddle`. The fork cases that call libc's `fork()` need it, and under `CI` a fork case that skips fails instead.
- Source builds need libclang; with the `libclang` gem, `ext/mini_racer_rs/extconf.rb` also passes GCC's include directory to bindgen.
- Each git worktree needs its own `npm ci` before the commit hooks can run, and `git submodule update --init` before the upstream suites or `rake test` (the ExecJS autodetect test) can run.
- The upstream suites run from their submodule (`vendor/mini_racer` or `vendor/execjs`) with `BUNDLE_GEMFILE`, `RUBYOPT`, `MINI_RACER_RS_UPSTREAM_REPORT`, `MINI_RACER_RS_UPSTREAM_ROOT` and, for ExecJS, `EXECJS_RUNTIME` set by `test/upstream/run.rb`; run them through that script, not with `rake test` inside the submodule.
- A forked child takes over a single-threaded context only if its runner was idle at a fork that went through `Process._fork` or `Process.daemon`; every other inherited context raises `MiniRacer::RuntimeError` (`single-threaded runner: ...`). The child never frees or waits on anything inherited: it reads atomics and try-locks only. Processes are told apart by `process::fork::epoch()`, never by pid.
- V8's worker tasks never reach V8's own worker threads, which do not survive a fork: `process::ensure_initialized` points the platform at a copy of its vtable whose `NumberOfWorkerThreads` and `PostTaskOnWorkerThreadImpl`/`PostDelayedTaskOnWorkerThreadImpl` slots (6, 20, 21) lead to `engine::sys`, which posts to the current generation's pool (`process::workers`). V8's own pool is created with the one thread rusty_v8 cannot go below and never gets a task. Each process starts its pool's threads at its first worker task, as many as V8 would have run for the mode (the processors online, held to 1 through 16, or 1 under `:single_threaded`); a child never touches its parent's pool, and tasks queued there at the fork are abandoned. V8's idle workers wait on an Abseil condition variable with their records on their own stacks, so a child that posted to them read freed memory and aborted on Ubuntu's glibc, as mini_racer's children still do; the pool's idle threads wait on a std `Condvar` instead, and the child does not post to them either.
- A fork through `Process._fork` or `Process.daemon` waits, in both V8 platform modes, up to 500 ms for every runner to be idle or parked, then pauses the worker pool until the parent handler and waits up to 100 ms more for the tasks it is running to end (`fork::prepare`, `Workers::pause`); it goes ahead either way. Past either bound a child's new contexts are best effort again, and it refuses every inherited context.
- V8 accepts a code cache for any source of the same length and runs the code it holds, so `process::code_cache` finds an entry only by file name, startup snapshot, length and a digest keyed with the process's random `RandomState`; never key it by length or an unkeyed hash. A sighting's sampled digest finds nothing: it decides only whether a script was seen before, so its cache is built at the second sighting, and whether a context keeping its own copy computes the full digest; a context sharing the source computes it from the first sighting (`Plan::Compile(Some(key))`). The cache is built in `serve_one` after the dispatch, so it never counts against `timeout:`, and before the response, so a fork after the eval finds the runner idle; a `Building` claim makes contexts loading a script at once build it once and frees the key on any failure.
- A large script reads its source, from its first sighting and under the code cache's key, from one copy in `process::sources`, one byte a unit when every unit fits Latin-1 and two otherwise, as V8 stores a string of it. V8 reads a string's units for as long as the string lives and releases its reference through `sys::release_one_byte` or `release_two_byte` once, on whatever thread runs it: in a collection, in an isolate's teardown, or when it internalizes a live string, which hands the units to the internalized string or, if that one has its own, releases them then (`MigrateExternalString` in V8's `string.cc`), so those touch only the `Arc`'s count. The list drops a source only once its count is back to `held`, the references its own list and every ancestor's hold, so V8 never frees one: a forked child adds a reference to its parent's, never touches the parent's list and frees nothing it inherited, and an isolate a control block leaks keeps its strings' references. A copy no string reads that only one context ever read, as a script evaluated once has, goes at the next `Sources::units` call, that is the next large eval of a source shared or kept (`reading` takes the list's lock but sweeps nothing), which looks its own source up first; contexts are told apart by `Runtime::reader`, recorded under the list's lock (`Readers`), since V8's releases touch only the count. A copy no string reads that two or more contexts have read, read in turn or at once, a copy made again of one of the last 8 sources swept (`List::swept`), so short-lived contexts loading two scripts in turn convert each twice and then keep both, and every copy a forked child inherited stay resident, up to 8 sources or 256 MiB, until a new source needs its room: going idle and `low_memory_notification` release nothing, and a forked child that evicts an inherited copy drops only its own reference, so the copy stays for that process's life; one that inherited contexts it refuses still read counts as read there for good. Past 8 sources or 256 MiB still read, a context keeps its own copy, as do one with `max_memory:`, whose heap holds mini_racer's copy, and invalid UTF-8, whose replacements are left to V8's decoder; room is decided under the lock before a source is converted, from the fewest bytes it can take or, for one converted before and refused, invalid UTF-8 included, the size the list remembers. `MINI_RACER_RS_CODE_CACHE=off` turns sharing off with the cache. A context reading a shared source reports it in `heap_stats`' `external_memory`, by its length in characters, and not in its `used_heap_size` (`behavior:shared-source-heap-stats@ruby`).
- An eval with no file name in one of two shapes runs a template its context compiled once instead of compiling the source (`fast_calls`, `runner::fast_call`): ExecJS 2.10.2's `call`, `(<path>.apply(this, <JSON array>))`, and react-rails 3.2.1 and 3.3.1's render, `compose_js`'s wrapper, whitespace and all, in ExecJS's parentheses around one `this.ReactRailsUJS.serverRender('<function>', '<component>', <props>)`. The template is a top-level script like the source, with each literal replaced by a call to a native function held in a global `const` with a random name, so frames, line and column numbers, messages and `this` are the source's. It reads a render's values as the source would only while the call line runs once, at the wrapper's top level, so the code before and after the call must compile alone as a function body and hold no backtick, `eval`, `caller`, `\u` escape, or `arguments` other than as a property after a `.` on the same line, both checked once per template and kept with it; a source that starts and ends as a refused template takes the normal path unread. Short of reflection (`CallSite#getFunction` through `Error.prepareStackTrace`, or `caller` and `arguments.callee` through names built at run time), the call line then runs once, synchronously, at the wrapper's top level. Parity is the bar: whatever the recognizer or V8's JSON parser is not sure of (another shape, values that are not JSON, `__proto__` in any spelling, nesting past 128, a line break in a render's props, a template over 1 MiB, `verbose_exceptions:`) takes the normal path, as does a source equal to the context's last fast call, which V8's compilation cache runs faster from its second time; a new shape lands only with tests pinning its outcomes to mini_racer 0.22.1. Only reflection still tells the paths apart, the approved deviation `behavior:fast-calls@ruby`: `CallSite#getScriptHash`, `CallSite#getPosition` past the hoisted literals, and a render's wrapper, which sloppy code reaches through `caller` or `CallSite#getFunction`: its source shows the reads, and calling it again runs the call with no values outside a fast call and with that call's values during one; and `Context#heap_snapshot` shows the reader's `const`. `MINI_RACER_RS_FAST_CALLS=off` (unstable, read once per process) sends every eval down the normal path.
- V8 reads a context's startup blob for as long as its isolate lives (each context it makes from it, each code cache it checks), so `ContextConfig::snapshot` stays in the control block, which the runner holds until it has dropped the isolate, and `sys::startup_data` hands V8 the shared bytes rather than a copy; a snapshot build holds its base the same way, and a control block that leaks an isolate leaks its blob with it. A `MiniRacer::Snapshot` makes its `SnapshotBlob` at a `Context.new` and reuses it, through a `WeakSnapshotBlob`, while a context made from it lives and its String, which `dump` hands out, holds the same bytes, as a mini_racer context starts from whatever that String holds; once its contexts are gone it holds only the String. `SnapshotBlob::check` follows V8 15.2's blob layout (`SnapshotImpl` in V8's `snapshot.cc`): the header, the version through V8's own check, and that each section opens with the same magic number (its top half `0xC0DE`) and fits its recorded payload. It never checks a checksum, so a blob V8 reads despite a damaged byte in a section's payload, or with bytes after its last section, still loads as in mini_racer, though a damaged section header is refused even where V8 would skip that section; what it refuses, and a warmup of an empty snapshot, raise `MiniRacer::SnapshotError` where mini_racer aborts the process.
- A `Context#call`'s arguments are built by the runner (`request::read`) rather than V8's deserializer, which makes every array holey, so V8 serialized a returned argument as a sparse array. V8's deserializer builds objects faster than the runner's one API call per property, so the encoder counts the hashes it writes and their pairs (`CallRequest`), and the runner builds only a call with at most 4 pairs in all or at most 2 per hash on average (`request::worth_building`); any other call V8 reads whole, as before. The runner builds numbers, BigInts, strings, dates, back references, packed arrays and objects; V8 reads a two-byte string for it from that string's bytes alone, which V8's API would make one-byte where it fits. A binary (V8's API aborts the process where its deserializer throws when it cannot allocate the buffer), a key that is neither a string nor an int32, a key given twice, an array inside itself, an object of more than 64 keys and nesting past 64 leave the whole request to V8, decided from its bytes before the runner makes any value (`request::buildable`): objects made for a call then refused leave V8's read of it the shapes they generalized, so it writes an integer field back as a double, and hold their memory under `max_memory:` while V8 reads the call again. A termination requested while the runner builds leaves the rest to V8 too: V8's deserializer acts on one before each value, so the builder checks `ControlBlock::termination_requested` before the request and before each value, and one requested before the dispatch refuses it first (`TermCell::refuses`). The flag is set before anything asks V8 to terminate and cleared only once V8 has cancelled, so every `terminate_execution` goes through `IsolateTerminator` or `runner::terminate`.
- mini_racer sends a String's bytes as UTF-8 unless its encoding is ISO-8859-1 or UTF-16LE, so every one of them that is all ASCII goes as one-byte text instead, the same characters, which V8 copies where it would scan for the first non-ASCII byte (`Encoder::string`). Whether it is ASCII comes from the coderange Ruby keeps in the String's flags (`rb_raw::cached_ascii`), else from its bytes, never from `rb_enc_str_coderange`: that scan checks each character of non-ASCII text, which made a call with an unscanned 1 MB non-ASCII String several times slower. Nothing writes the coderange back, so a String sent again is read again. A coderange a C extension left stale after changing the bytes would be trusted, as Ruby itself trusts it.
- A primitive result (a small integer, a heap number other than NaN, a string, a boolean, null, undefined) is written by `serialize::primitive` without V8's serializer, under the format version V8 writes, read once per context: for these V8's serializer checks for no termination and runs no script, and the microtasks it would run as it returns have run as the script returned. A heap number holding an int32 is still a double to V8, so `sys::is_smi` reads the handle's tagged word, which assumes V8 built without direct handles; `crates/mini_racer_engine/tests/results.rs` compares each kind with V8's own bytes.
- A `compat.toml` status describes CRuby. Implementing a planned method without marking it `done` fails `compat:check` with `TODO_BUT_IMPLEMENTED`; a planned method that exists before what it calls works (`write_heap_snapshot`) lists that in `depends_on`.
- `rake` needs the lint group installed; without it (the TruffleRuby CI job), run `tools/compat/reflect.rb` and `tools/compat/check.rb` directly.
- A string key of an object or a map is made interned (`Visitor::key`, `rb_raw::interned_utf8`), the frozen String `Hash#[]=` would keep in place of a new one, so it is the object mini_racer's key is; keys of objects inside arrays and sets go through a cache for the decode, as names do in json 3.1's parser (63 keys of at most 55 bytes that start with a letter). A key with a lone surrogate stays a UTF-16LE String for the hash to intern, the function marker stays a `JavaScriptFunction` (an object's key is then its `to_s`), and a numeric key still goes through `to_s`; keys of arrays, which are dropped, and an error's fields are made as before.
- The decoder recurses once per level of a result, up to 95, so whatever its recursive functions keep inline is repeated on the stack of the fiber or thread that decodes: in a release build that is `value` and the container being read, about 300 bytes a level for every shape. A key is read in `entry_key`, out of line, and read again by `value` when it is not a string, since handing `value` its tag split `value` in two and pulled every container into one frame over twice as large; `Pairs::start` and `KeyCache::start` make the decoder's buffers out of line too. `ContextDeepResultsTest` in `test/ruby/context_test.rb` decodes each shape 95 deep in a fiber and a thread at Ruby's default stack sizes; a debug build's frames are many times larger, so it overflows a 256 KiB fiber stack a release build decodes in.
- A decoded hash takes its pairs when it ends, in one `rb_hash_bulk_insert` into its still empty table (`Pairs`), which keeps a repeated key as `Hash#[]=` does: the first key's place and object with the last value. A key that is not a String of class String, an Integer, a Float, a Symbol, nil, true or false (`rb_raw::plain_key`), such as a Hash or an Array that refers back to an open hash, first puts every open hash's waiting pairs in, so its `hash` and `eql?` see each one as mini_racer has built it by then, and goes in by itself; a hash that already holds pairs takes the rest one by one, since a bulk insert would rehash it whole. Past 128 values the waiting pairs move to a `gc_root::Spill`, whose mark pins them.
- A Latin-1 or UTF-16 string value is transcoded in one pass into the decoder's scratch buffer (`RubyVisitor::scratch`), which has room for the longest UTF-8 the text could be (two bytes per Latin-1 byte, three per UTF-16 unit) and is zeroed only as it grows, then copied into its String with one `rb_enc_str_new`; text whose UTF-8 could pass 64 KiB (`SCRATCH`) is measured first (`latin1_utf8_len`, `utf16le_utf8_len`) and gets a buffer of exactly its size, freed once copied, since the longest it could be would commit up to three times its size next to the String. Writing into an `rb_str_buf_new` String and setting its length instead, as json 3.1's parser does for escaped strings, measured slower: it takes three Ruby calls, two of them under `rb_protect`, and a buffer zeroed or measured first, which cost more than the copy saves. A UTF-16 string with a lone surrogate still becomes a UTF-16LE String, as in mini_racer.
- mini_racer 0.22.1 aborts the whole process (signal 6) on some values, such as a `Map` with a function key; the differential run records that as a `crash` outcome, and worker stderr is in `tmp/diff/<role>-worker.log`. A worker that exits with a status instead is a harness failure and stops the run.
- Plain V8 has no `MessageChannel` or `TextEncoder`, which React's server renderer reaches for when it loads; `test/consumers/js/entries/ssr-globals.js` provides the stand-ins SSR setups on mini_racer use. Bundles are built into `tmp/consumers/bundles` by `npm run build` in `test/consumers/js`.
